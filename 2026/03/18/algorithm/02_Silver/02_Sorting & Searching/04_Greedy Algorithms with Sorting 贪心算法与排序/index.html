Greedy Algorithms with Sorting 贪心算法与排序

Greedy Algorithms with Sorting

贪心算法与排序

贪心算法在每一步选择当前最优的选项，通常与排序配合使用。

一、贪心算法基础

贪心算法的核心是价值函数：决定哪个选择是最优的。

  • 要最大化某个值 → 每次选择最大的
  • 要最小化某个值 → 每次选择最小的

关键：贪心算法需要证明其正确性，通常通过交换参数证法（exchange argument）。

二、例题1：学习算法（Studying Algorithms）

题目来源: Codeforces - Very Easy

题目描述：Steph 有 X 分钟时间学习算法，有 N 个算法，第 i 个需要 a_i 分钟。求最多能学多少个算法。

约束条件：1 ≤ X ≤ 10^4，1 ≤ N ≤ 100，1 ≤ a_i ≤ 100

解题思路

  1. 贪心策略：先学习用时最短的算法
  2. 排序：将 a_i 按升序排列
  3. 累加：依次选择，直到时间用完

正确性证明

假设有两个算法 A（用时短）和 B（用时更长）。如果最优解先选 B，那么把 B 换成 A： - 不会增加总时间 - 不会减少可选算法的数量

因此，先选最短的总是最优的。

代码实现

algorithms.sort()
count = 0  # 已用时间
i = 0
while i < N and count + algorithms[i] <= X:
    count += algorithms[i]
    i += 1
print(i)

时间复杂度：O(N log N)

三、例题2：活动安排（Movie Festival）

题目来源: CSES - Easy

题目描述：有 N 个活动，每个活动有开始时间和结束时间。每次只能参加一个活动，参加必须全程参加。求最多能参加多少个活动。

贪心策略对比

错误策略：选择下一个最早开始的

反例： 

活动: [(0,6), (5,10), (6,7)]
按"最早开始" → 只选1个
最优解 → 选2个 [(0,6), (6,7)]

正确策略：选择下一个最早结束的

核心思想：选择结束最早的活动，为后续活动留出更多时间。

正确性证明

设有两个活动 E1 和 E2，E1 比 E2 结束得更早。

  • 如果能参加 E2 之后的某个活动 X，那么 X 也能接在 E1 之后（因为 E1 结束更早）
  • 所以选择 E1 不会比选择 E2 差
  • 选择 E1 能让后续选择集合更大

因此，总是选择最早结束的活动是最优的。

代码实现

events.sort(key=lambda x: x[1])  # 按结束时间排序
current_end = -1
ans = 0

for start, end in events:
    if start >= current_end:  # 可以参加
        current_end = end
        ans += 1

print(ans)

时间复杂度：O(N log N)

四、贪心算法失效的例子

例1：硬币找零（Coin Change）

问题：给定硬币面额，求组成目标值所需的最少硬币数。

反例： - 面额：{1, 3, 4} - 目标值：6 - 贪心解：4 + 1 + 1 = 3 个硬币 - 最优解：3 + 3 = 2 个硬币

结论：贪心只在特定面额系统下有效（如美元、欧元）。

例2：背包问题（Knapsack）

问题：每个物品有重量和价值，求价值最大的选择。

反例：

物品 重量 价值 价值/重量
A 3 18 6
B 2 10 5
C 2 10 5
  • 容量：4
  • 贪心解：选 A，价值 18
  • 最优解：选 B + C，价值 20

结论：背包问题需要用动态规划（Gold 级别）解决。

五、总结

贪心算法适用条件

  1. 最优子结构：局部最优能导出全局最优
  2. 贪心选择性质：每步选择都是当前最优

常见贪心策略

问题类型 贪心策略
时间安排 选最早结束的
背包（价值/重量） 无通用贪心
硬币找零 仅特定面额
活动选择 按结束时间排序

关键要点

  • 先排序，再贪心
  • 用交换参数证法证明正确性
  • 注意特判反例场景
